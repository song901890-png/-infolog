# 매일 1편 자동 작성 지침

이 문서는 `npm run daily`(scripts/daily-publish.mjs)가 Claude 를 무인 실행할 때 읽히는 지침입니다.
호출 메시지에 `DATE=YYYY-MM-DD` 와 `CATEGORY=<slug>` 가 주어집니다. **정확히 글 1편**만 작성하세요.

## 해야 할 일

1. `src/consts.ts` 의 `CATEGORIES` 에서 CATEGORY 의 이름·설명을 확인합니다.
2. `src/content/blog/` 의 기존 글을 모두 훑어 제목·slug·주제를 파악합니다. **이미 다룬 주제와 겹치지 않는** 새 주제를 고릅니다.
3. `src/data/links.json` (공식 링크 허브 `/links/` 의 데이터)을 읽어 링크할 수 있는 섹션 id 를 확인합니다.
4. 필요하면 웹 검색으로 사실(일정·요금·서비스 변경 등)을 확인합니다. 확인하지 못한 수치·날짜는 쓰지 않습니다.
5. `src/content/blog/<slug>.mdx` 파일 1개를 새로 만듭니다. 다른 파일은 수정하지 않습니다.

## 카테고리별 주제 방향

- `guide` (링크모음): 공식 사이트 링크모음, 공식 주소 찾는 법, 주소가 바뀌었을 때 확인 방법, 가짜·피싱 주소 구별, 접속이 안 될 때 해결법, 즐겨찾기·바로가기 관리 등 **링크·주소와 관련된 실용 정보**.
- `sports` (스포츠중계·프리뷰): 리그·대회 일정, 합법 중계 채널·플랫폼, 빅매치 프리뷰, 공식 중계 사이트 링크모음 성격의 글.
- `webtoon` (웹툰·플랫폼): 웹툰 플랫폼 비교, 합법 무료 이용 팁, 신작·완결 소식, 공식 웹툰 사이트 링크모음 성격의 글.
- `ott` (OTT·영화드라마): OTT 요금제·혜택 비교, 신작 공개 일정, 해지·환불 방법, 공식 OTT 사이트 링크모음 성격의 글.
- `anime` (애니·웹소설): 애니메이션 합법 스트리밍 플랫폼, 웹소설 플랫폼 비교, 무료 이용 팁, 신작·완결 소식, 공식 사이트 링크모음 성격의 글.
- `security` (피싱·보안): 스미싱·피싱 사이트 구별, 계정 보안(2단계 인증·비밀번호 관리), 개인정보 유출 대처, 신고 방법.
- `weekly` (주간 이슈 요약): 그 주의 스포츠·웹툰·OTT·보안 이슈를 3~5개로 요약. slug 는 `weekly-issue-YYYY-MM-wN` 형식.

## 반드시 지킬 원칙

- **공식·합법 서비스만** 다룹니다. 저작권 침해 사이트, 불법 스트리밍·도박 사이트의 이름·주소·우회 접속 방법은 절대 쓰지 않습니다.
- 외부 링크는 운영사 공식 사이트나 공공기관 등 **직접 확인한 공식 주소**만 넣습니다. 추측한 URL 금지.
- 과장·낚시성 표현, 확인되지 않은 사실, 다른 글을 베낀 문장을 쓰지 않습니다.

## 파일 형식

파일명(slug)은 영문 소문자·숫자·하이픈만 사용합니다(예: `official-webtoon-site-address-check`).

```mdx
---
title: "핵심 키워드를 앞쪽에 둔 제목 (28자 안팎, 최대 70자)"
description: "검색 의도에 대한 답을 요약한 설명 (80~120자, 최대 160자)"
pubDate: DATE 값 그대로
category: CATEGORY 값 그대로
tags: ["태그1", "태그2", "태그3", "태그4"]
summary:
  - "핵심 요약 1"
  - "핵심 요약 2"
  - "핵심 요약 3"
faq:
  - question: "독자가 실제로 검색할 법한 질문"
    answer: "2~3문장의 직접적인 답변"
  - question: "두 번째 질문"
    answer: "답변"
  - question: "세 번째 질문"
    answer: "답변"
draft: false
---

도입부 2~3문장 (첫 문단에 핵심 키워드 포함)

<SoftCTA />

## 소제목
...
```

## 본문 품질 기준 (빌드의 SEO 점검 항목)

- 본문 **1,500자 이상**(공백 제외), `##` 소제목 **3개 이상**, 마지막은 `## 마무리`.
- **다른 글 링크 2개 이상**: 기존 글을 `[제목](/slug/)` 형태로 자연스럽게 연결. 실제 존재하는 slug 만 사용.
- 공식 링크 허브 연결 1개 이상: `[…](/links/)` 또는 `[…](/links/#섹션id)`.
- **공식 출처 외부 링크 1개 이상**.
- 표·목록을 적절히 써서 훑어 읽기 쉽게 구성. 본문에는 `# ` (H1) 을 쓰지 않습니다.
- `<SoftCTA />` 는 import 없이 도입부 뒤에 1회 사용.
- 이미지 파일은 만들 수 없으므로 본문에 이미지를 넣지 않습니다.
- title·description 은 기존 글과 중복되면 안 됩니다. frontmatter 값에 큰따옴표(")가 들어가면 YAML 이 깨지므로 작은따옴표나 「」를 씁니다.

## 끝나면

만든 파일 경로와 제목을 한 줄로 출력하고 종료합니다. 빌드·git 작업은 스크립트가 처리하므로 실행하지 않습니다.
